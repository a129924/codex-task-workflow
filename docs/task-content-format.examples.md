# Task 內容情境示例

依 [內容規則](task-content-format.md) 與 [Markdown 模板](task-content-format.template.md) 展示五組情境、十份完整紀錄。所有識別、專案、來源事實與 `example://` 位置均為虛構；不是實際 YouTrack 紀錄、可存取連結或真人驗收結果。「本人手寫版」是模擬本人直接記錄的範例，「Agent 整理版」是根據同組來源事實編寫的範例，不宣稱已由真人填寫或實際 Agent 操作驗證。

每組的來源事實是兩版本共同的唯一依據。A1 等編號指本頁的虛構事實段落，供核對內容；不是另附的參考資料。每份紀錄都保留完整 metadata 與 snapshot；遮蔽來源事實、參考內容及原對話後，仍可從紀錄回答目的、方向或未知處、階段、下一步或待釐清處、阻礙，以及結案結果或原因。

D2：之後在這個虛構情境中，提供者確認匯出清單能離線讀取，目的達成，明確決定完成結案。現在階段 Close、結案類型完成，無未解決問題及阻礙。參考 PR 由提供者轉述合併狀態，Agent 未讀原件、能否存取未確認；用途為追查匯出變更。重要變更保留 PR 到 Close 及結案理由。這不是實際使用者驗收證據。

## 不補造的反例

以下同樣是虛構來源，示範不能推導定案的邊界，不是新增的有效 Task。

| 來源 | 不可寫成 | 應保留的缺口 |
| --- | --- | --- |
| F1：「想用某個新框架」，未說希望解決什麼問題 | 「目的：提升效能」，或以此建立有效 Idea | `待釐清：希望解決什麼問題或達成什麼結果`；先釐清目的，再依已知目的命名與建立 Idea |
| F2：已知目的為減少月帳手動整理；一段說直接匯入 CSV，另一段說先手動輸入，未確認哪個已被決定 | 默認後一段為目前方向，補寫理由與實作下一步 | `方向：待釐清：直接匯入 CSV 與先手動輸入的來源互相矛盾`；`主要理由：待釐清：未確認採用哪個方向及理由`；`下一步：待釐清：尚未確認下一個行動` |

F2 的已知目的可留存 Idea，但不能把矛盾當成方向變更已定案，也不能寫「無阻礙」；有無阻礙未確認時仍填 `待釐清：尚未確認有無阻礙`。若來源未提供決策行動，整理者不自行把「去確認某人」寫成已授權下一步。

這些範例僅供文件情境演練；實际產品建立、查詢、更新、結案與系統欄位映射，均不由本頁宣告通過。
