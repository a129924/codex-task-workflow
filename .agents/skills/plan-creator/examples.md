# Plan creator examples

All file-producing examples require actual Default, selected feature and exact
existing authorized paths. Plan or Default without write authority instead
returns a complete conversation draft with intended paths and proposed states;
unknown mode stops without writes. Illustrative paths never claim disk existence,
actual review-ready state or approval. Optional analysis is not made mandatory.

## Positive: local development tool

Plan a bounded `.agents/skills/example/SKILL.md` change with exact companion
paths, Implementer ownership, README navigation modification if needed, and
GOAL.md / docs/task-workflow.baseline.md ReadOnly. State stable-library intent
absent, no VERSION or release change. Use all 11 required sections, current
planned status, next actor Plan-Creator and action Author the bounded plan.
Use the native independent reviewer JSON schema as a contract, not a verdict.

## Positive: analysis priority

When both analysis/topic/requirements.md and technical-spec.md exist, map the
plan to the technical spec and preserve the business intent. When either is
missing, name it in the semantic warning. Do not silently substitute chat.

## Negative: missing contracts or guessing

If either shared contract is absent, stop before drafting. Do not invent vague
paths such as `docs`, release timing, a direct planned -> approved transition,
or an approval authored by the plan author.

## Negative: scope and actor drift

Reviewer logging and Observer routing do not belong in Implementation Steps.
A README link does not authorize VERSION or registry changes. Stable-library
promotion is BLOCKED without a separately approved publishing contract.

## Positive: draft without file authority

With complete identified frozen scope but no Default file-write authority,
produce all eleven sections in conversation at the intended topic path. Declare
analysis absent by a named warning if optional files are absent; do not invent
requirements/spec files. State that phase fields are proposed and nothing was
written. Missing required frozen scope stops rather than fills placeholders.

## Actual phase ownership

The author records planned, creator-in-progress and review-ready only under
exact existing Default file authority. A distinct Reviewer then actually
acknowledges start; the authorized owner records reviewer-in-progress before
resumed review. Owner records approved only after that actual native verdict.
This example describes ordering, not an issued acknowledgement or approval.
